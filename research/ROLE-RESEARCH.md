# Role Research: Junior Cloud Engineer (AWS-focused)

## Target Role

**Junior Cloud Engineer, AWS-focused** — an entry-level role supporting and maintaining AWS-based infrastructure under the guidance of senior engineers. I picked this over 'Cloud Support' because that's mostly customer troubleshooting, and over 'Junior DevOps' because that leans more into CI/CD pipelines than I want to start with.

## In-Demand Tools / Keywords (appear across 3+ postings)

| Keyword | Why it matters |
|---|---|
| AWS core services (EC2, S3, IAM, VPC, Lambda) | Baseline in every posting — the "must-have" cluster |
| Terraform | Infrastructure-as-code is expected even at junior level, not just "nice to have" |
| Docker | Containerization fundamentals assumed |
| Kubernetes / EKS | Increasingly listed even for junior roles, usually as "familiarity" not mastery |
| CI/CD pipelines | Deployment workflow exposure — GitHub Actions, Bamboo, Jenkins interchangeably accepted |
| Python or Bash scripting | Automation ability is a filter question, not a bonus |
| Linux administration | Every posting assumes comfort at the command line |
| Git / GitHub / Bitbucket | Version control fluency taken for granted |
| Cloud security basics (IAM, Security Groups, least-privilege) | Shows up even in non-security-titled roles |
| Monitoring/observability (CloudWatch, Grafana) | Signals "can operate," not just "can deploy" |
| AWS Certified Cloud Practitioner (or Associate-level cert) | The single most common credential requested or preferred |

## What a Strong Resume Looks Like Here

**Gets a callback:**
- Leads with specific AWS services touched (not "worked with AWS") — e.g., "provisioned VPC, EC2, and IAM roles via Terraform for a 3-tier app"
- Quantifies outcomes: cost reduced, deploy time cut, uptime maintained
- Shows at least one artifact a reviewer can check — a GitHub repo, a Terraform module, a small CI/CD pipeline
- Uses the same verbs as the posting (deploy, provision, automate, monitor) rather than generic ones (helped, worked on)
- Certifications listed prominently near the top, not buried

**Gets filtered:**
- Lists tools with no evidence of use ("Familiar with: AWS, Docker, K8s, Terraform, Ansible, Jenkins...") — looks like someone just     copied the job posting back at them
- No links to code, no metrics, no scale indicated
- Generic bootcamp-project language with no infrastructure specifics
- Career-change resumes that lead with unrelated prior experience instead of the cloud projects

## Target Profile (for the tailoring engine to optimize toward)

A candidate transitioning into cloud engineering with hands-on, project-based AWS experience (EC2, S3, IAM, VPC, Lambda) reinforced by infrastructure-as-code practice in Terraform and containerization with Docker/Kubernetes; comfortable scripting in Python or Bash and operating in Linux environments; has built or contributed to at least one CI/CD pipeline and can speak to monitoring/observability and basic cloud-security practices (least-privilege IAM, security groups); ideally holds or is pursuing the AWS Certified Cloud Practitioner (or a Solutions Architect Associate) certification; and can point to a public repo or portfolio project as proof of the above rather than asserting it as a list of tools.
